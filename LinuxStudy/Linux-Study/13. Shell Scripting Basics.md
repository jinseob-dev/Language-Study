# **What is a Shell Script?**

Shell scripting lets you bundle long or repetitive terminal commands into a single script - like writing a to-do list your computer can follow automatically.  
Think of it like a recipe. Instead of remembering each cooking step, you write them down and follow the list. Shell scripts work the same way for computer tasks.  
Shell scripts are powerful because they can:
- Automate repetitive tasks
- Combine multiple commands into one action
- Process files in batches 
- Schedule tasks to run automatically
The most common shell on Linux systems is <mark>bash</mark> (Bourne Again Shell). When you create a shell script, you're essentially writing instructions for bash to follow.  
Shell scripts typically have a <mark>.sh</mark> extension, like 
<mark>backup.sh</mark> or <mark>setup.sh</mark>. However, the extension isn't required - Linux identifies scripts by their content, not their name.
Every shell script starts with a special line called a "shebang"  that looks like this:
`#!/bin/bash`
This line tells the system which program should run the script. The <mark>!#</mark> symbols are followed by the path to the bash interpreter.  
Shell scripts can be as simple as two commands or as complex as full applications. They're used everywhere automation tasks.  


# **Writing Your First Script**

Creating your first shell script is straightforward.  
You'll use a text editor to write commands and save them in a file.  
Let's create a simple script that displays information about your system. 
Open your favourite text editors. If you're new to Linux, <mark>nano</mark> is beginner-friendly:
`nano my_firstf_script.sh`
Type the following content:
`#!/bin/bash`
`echo "Welcome to my first script!"`
`echo "Today's date is:"`
`date`
`echo "Current user:"`
`whoami`
`echo "Current directory:"`
`pwd`
Save the file and exit the editor. In nano, press <mark>Ctrl+X</mark>, then <mark>Y</mark>, then <mark>Enter</mark>.  
Let's break down what this script does:  
The first line <mark>#!/bin/bash</mark> tells Linux to use bash to run this script.  
The <mark>echo</mark> command prints text to the screen. You can use it to display messages or information.  
The <mark>date</mark> command shows the current date and time.  
The <mark>whoami</mark> command displays your username.  
The <mark>pwd</mark> command shows your current directory path.  
Each command runs in sequence, just like if you typed them individually in the terminal.  
Shell scripts follow the same syntax as commands you type in the terminal. Any command that works in your shell will work in a script.  
This simple script demonstrates the basic structure that all shell scripts follow: shebang line, followed by commands, one per line.


# **Making Scripts Executable**

After writing a script, you need to make it executable before you run it. By default, new files don't have execute permissions.  
Check your script's current permissions:  
`ls -l my_first_script.sh`
You'll see something like:
`-rw-r--r-- 1 user user 145 Dec 10 10:30 my_first_script.sh`
The first part <mark>-rw-r--r--</mark> shows the permissions. The absence of <mark>x</mark> means the files isn't executable.  
To make your script executable, use the <mark>chmod</mark> command:
`chmod +x my_first_script.sh`
Now check the permissions again:
`ls -l my_first_script.sh`
You should see:
`-rwxr-xr-x 1 user user 145 Dec 10 10:30 my_first_script.sh`
The <mark>x</mark> letters indicate execute permission for different user groups.
Now you can run your script in several ways:
`./my_first_script.sh`
The <mark>./</mark> tells the shell to look for the script in the current directory.  
Alternatively, you can run it with bash directly:
`bash my_first_script.sh`
This method works even without execute permissions because you're explicitly telling bash to interpret the file.  
You can also move executable scripts to directories in your <mark>PATH</mark> (like <mark>/usr/local/bin</mark>) to run them from anywhere without the <mark>./</mark> prefix.  
Remember: making scripts executable is a one-time step. the script keeps its permissions until you change them.


# **Variables and User Input**

Variables in shell scripts store information that you can use throughout your script. They make scripts flexible and reusable. 

**Creating  Variables**

Create variables by assigning values without spaces around the equals sign:  
`#!/bin/bash`
`name="John"`
`age=25`
`greeting="Hello there"`
`echo $name`
`echo $age`
`echo $greeting`
Access variable values by putting a <mark>$</mark> before the variable name. You can also use <mark>${variable_name}</mark> for clarity:
`echo "I am ${name} and I am ${age} years old"`

**Getting User Input**

The <mark>read</mark> command captures user input and stores it in a variable:
`#!/bin/bash`
`echo "What is your name?"`
`read username`
`echo "Hello, $username1"`
You can prompt and read input in one line:
`read -p "Enter your age: " age`  

**Arithmetic operations**

The basic syntax involves wrapping your mathematical expression inside double parentheses with a dollar sign prefix:  
`#!/bin/bash`
`result=$((5 + 3))`
`echo $result`
Output:
`8`
It supports all standard mathematical operators including parentheses for grouping operations:
`#!/bin/bash`
`a=10`
`b=3`
`c=2`
`result=$(((a + b) * c))`
`echo $result`
Output:
`26`
The expression <mark>(a + b) * c</mark> first adds 10 and 3, then multiplies by 2, giving us 26.  

**Special Variable**

Shell scripts have built-in variables:
- <mark>$0</mark> - Script name
- <mark>$1, $2, $3. . .</mark> - Command line arguments
- <mark>$#</mark> - Number of arguments
`#!/bin/bash`
`echo "You are running:a $0"`
If your script is named <mark>welcome.sh</mark>, <mark>$0</mark> will be <mark>./welcome.sh</mark> or just <mark>welcome.sh</mark> depending on how you run it.  
Arguments <mark>$1</mark> through <mark>$9</mark> hold the first nine arguments passed to your script:
`#!/bin/bash`
`echo "Fist arg: $1"`
`echo "Second arg: $2"`
`echo "Third arg: $3"`
`# ...`
Example output:
`./script.sh cat dog fish`
`First arg: cat`
`Second arg: dog`
`Third arg: fish`


# **Conditional Statements**

Conditional statements let your scripts make decisions based on different conditions. They're' essential for creating intelligent, responsive scripts.

**Basic If Statement**

The <mark>if</mark> statement checks a condition and runs commands only if the condition is true:
`#!/bin/bash`
`read -p "Enter a number: " number`
`if [ $nimber -gt 10 ]; then`
	`echo "The number is greater than 10"`
`fi`
The condition goes between square brackets <mark>[ ]</mark>. The comparison operator <mark>gt</mark> means "greater than".  

**Common Comparison Operators**

For numbers:
- <mark>-eq</mark>: equals
- <mark>-ne</mark>: not equals
- <mark>gt</mark>: greater than
- <mark>-ge</mark>: greater than or equal
- <mark>-lt</mark>: less than
- <mark>-le</mark>: less than or equal
For strings:
- <mark>=</mark>: equals
- <mark>!=</mark>: not equals
`if [ "$name" = "admin" ]; then`a
	`echo "Welcome, administrator!"`
`fi`
Always quote string variables to handle spaces properly.

**If-Else Statements**

Add an <mark>else</mark> clause to handle cases when the condition is false:
`#!/bin/bash`
`read -p "Enter your age: " age`
`if [ $age -ge 18 ]; then`
	`echo "You are at least $age years old, so you are an adult"`
`else`
	`echo "You are a minor"`
`fi`
This script prompts the user to enter their age and stores it in the variable <mark>code</mark>. It then checks if the age is greater than or equal to 18 using an if statement. If true, it prints "You are an adult"; otherwise, it prints "You are a minor".

**Multiple Conditions**

Use <mark>elif</mark> for multiple conditions:
`#!/bin/bash`
`read -p "Enter your score: " score`
`if [ $score -ge 90 ]; then`
	`echo "Grade: A"`
`elif [ $score -ge 80 ]; then`
	`echo "Grade: B"
`elif [ $score -ge 70 ]; then`
	`echo "Grade: C"`
`else`
	`echo "Grade: F"`
`fi`
This script asks the user to enter their score and stores it in the <mark>score</mark> variable. It then uses <mark>if</mark>, <mark>elif</mark>, and <mark>else</mark> statements to determine the grade: A for  scores 90 and above, B for 80-89, C for 70-79, and F printed based on the input.  


# **Loops in Scripts**

Loops allow your scripts to repeat tasks  multiple times without writing the same code repeatedly. They're perfect for processing multiple files or repeating actions.  

**For Loops**

For loops iterate over a list of items:
`#!/bin/bash`
`for animal in cat dog fox; do`
	`echo "$animal"`
`done`
Output:
cat
dog
fox
You can loop through numbers:
`#!/bin/bash`
`for i in {1..5}; do`
	`echo "Count: $i"`
`done`
Output:
Count: 1
Count: 2
Count: 3
Count: 4
Count: 5
Loop through files in a directory:
`#!/bin/bash`
`for filie in *.txt; do`
	`echo "Processing $file"`
	`# Add your file processing commands here`
`done`
Output:
Processing doc1.txt
Processing somefile.txt
Processing tmp.txt
Processing tmp2.txt

**While Loops**

While loops continue running as long as a condition remains true:
`#!/bin/bash`
`counter=1`
`while [ $counter -le 5 ]; do`
	`echo "Counter: $counter"`
	`counter=$((counter + 1))`
`done`
This script initialises a variable <mark>counter</mark> with the value. It uses a <mark>while</mark> loop to repeatedly print the current value of <mark>counter</mark> as long as it is less than or equal to 5. After each loop, it increments <mark>counter</mark> by 1, so the loop runs five times, printing "Counter: 1" to "Counter: 5".  

**Reading File Lines**

Use while loops to process file contents line by line:
`#!/bin/bash`
`while read line; do`
	`echo "Line: $line"`
`done < input.txt`
This script reads a file named <mark>input.txt</mark> line by line using a while loop. For each line it reads, it prints the line prefixed with "Line: ". The loop continues until all lines in the file have been read.  

**Infinite Loops with Break**

Sometimes you need loops that run until a specific event occurs:
`#!/bin/bash`
`while true; do`
	`read -p "Enter 'quit' to exit: " input`
	`if [ "$input" = "quit" ]; then`
		`break`
	`fi`
	`echo "You entered: $input"`
`done`
`echo "Goodbye!"`
This script runs an infinite loop that keeps asking the user to inter text. If the user types "quit", the loop breaks and ends. Otherwise, it prints back what the user entered, and after exiting the loop, it prints "Goodbye!".  
The <mark>break</mark> command exits the loop immediately.


# **Debugging Scripts**

Debugging helps you find and fix errors in your scripts. Even experienced programmers make mistakes, so knowing debugging techniques is essential.  

**Common Script Errors**

Scripts can fail for various reasons:
- Syntax errors (typos, missing brackets)
- Logic errors (wrong conditions)
- Permission issues
- Missing files or commands

**Verbose Mode**

Run your script with <mark>-v</mark> flag to see each command as it executes:
`bash -v my_script.sh`
This shows exactly which lines are running.

**Debug Mode**

Use <mark>-x</mark> flag to see commands and their results:
`bash -x my_script.sh`
This displays each command with a <mark>+</mark> prefix before execution.  
You can also add debug mode inside your script:  
`#!/bin/bash`
`set -x # Turn on debug mode`
`echo "This will show debug info"`
`set +x # Turn off debug mode`
`echo "This won't show debug info"`

**Adding Debug Output**

Insert <mark>echo</mark> statements to track your script's progress:
`#!/bin/bash`
`if [ ! -f "document.txt" ]; then`
	`echo "ERROR: document.txt not found!"`
	`exit 1`
`fi`
`echo "File exists, continuing..."`
The <mark>exit 1 </mark> command stops the script with an error code, which you can retrieve later using <mark>echo $?</mark>.
