# **Introduction to nano**

Text editors are essential tools for working with files in Linux. The <mark>nano</mark> editor is perfect for beginners because it displays helpful shortcuts right on the screen.  
To open <mark>nano</mark>, simply type:  
`nano`  
To edit existing file:  
`nano filename.txt`  
When <mark>nano</mark> opens, you'll see the main editing area and shortcuts at the bottom. The <mark>^</mark> symbol means hold the Ctrl Key. For example, <mark>^X</mark> means Ctrl+X.  

**Basic Navigation**

Use arrow keys to move around the text. The cursor shows your current position.  

**Essential Shortcuts**

The most important shortcuts are displayed at the bottom:  
- <mark>^X</mark> (Ctrl+X): Exit nano
- <mark>^O</mark> (Ctrl+O): Save the file (WriteOut)
- <mark>^W</mark> (Ctrl+W): Search for text
- <mark>^K</mark> (Ctrl+K): Cut current line
- <mark>^U</mark> (Ctrl+U): Paste cut text

**Creating Your First File**

Let's create a simple text file:  
`nano file.txt`  
Type some text, then press <mark>Ctrl+O</mark> to save. You'll see a prompt asking for the filename. Press Enter to confirm, then <mark>Ctrl+X</mark> to exit.  
The beauty of <mark>nano</mark> is its simplicity. Everything you need is. visible on screen, making it ideal for quick edits and learning Linux file editing basics.  

**Using vim Basics**

The <mark>vim</mark> editor is powerful but different from typical text editors. It has two main modes: Normal mode for navigation and Insert mode for typing text.  

**Starting vim**

Open <mark>vim</mark> with:  
`vim`  
Or edit a specific file:  
`vim filename.txt`  

**Understanding Modes**

When <mark>vim</mark> starts, you're in Normal mode. You cannot type text directly. To enter Insert mode, press <mark>i</mark>. You'll see <mark>-- INSERT --</mark> at the bottom.  

**Insert Mode*

In Insert mode, type text normally.  
1. Press <mark>i</mark> to enter Insert mode
2. Type your text
3. Press <mark>Esc</mark> to return to Normal mode

**Basic Navigation in Normal Mode**
- <mark>h</mark>: Move left
- <mark>j</mark>: Move down
- <mark>k</mark>: Move up
- <mark>l</mark>: Move right
Arrow keys also work, but vim users prefer these letter keys.  

**Essential Commands**

All commands work in Normal mode:  
- <mark>i</mark>: Enter Insert mode
- <mark>Esc</mark>: Return to Normal mode
- <mark>:w</mark>: Save file
- <mark>:q</mark>: Quit vim
- <mark>:wq</mark>: Save and quit
- <mark>:q!</mark>: Quit without saving  

**Your First vim Session**

`vim practive.txt`
Press <mark>i</mark>. type some text, press <mark>Ese</mark>, then type <mark>:wq</mark> and press Enter.  
While <mark>vim</mark> seems complex initially, these basics will get you started with file editing.  


# **Editing Files with gedit**

The <mark>gedit</mark> text editor provides a familiar graphical interface similar to Windows Notepad but with more features. It's perfect when you're using a desktop environment.  

**Starting gedit**

Launch <mark>gedit</mark> from the terminal:  
`gedit`  
Open a specific file:  
`gedit filename.txt`  
You can also open multiple files:
`gedit file1.txt file2.txt`  

**Interface Overview**

The <mark>gedit</mark> window contains:
- Menu bar with File, Edit, View oprions
- Toolbar with common buttons
- Main editing area
- Status bar showing line numbers and cursor position

**Basic Editing Features**

Unlike terminal editors, <mark>gedit</mark> works like any modern text editor:  
- Click anywhere to position the cursor
- Type normally to insert text
- Use Ctrl+C, Ctrl+V for copy and paste
- Drag to select text

**Useful Keyboard Shortcuts**

- <mark>Ctrl+N</mark>: New file
- <mark>Ctrl+O</mark>: Open file
- <mark>Ctrl+S</mark>: Save file
- <mark>Ctrl+F</mark>: Find text
- <mark>Ctrl+H</mark>: Find and replace
- <mark>Ctrl+G</mark>: Go to specific line number
- <mark>Ctrl+Z</mark>: Undo
- <mark>Ctrl+Y</mark>: Redo

**Working with Tabs**

When multiple files are open, <mark>gedit</mark> displays them as tabs. Click tabs to switch between tiles or use <mark>Ctrl+Alt+PageUp</mark> and <mark>Ctrl+Alt+PageDown</mark>.  
The <mark>gedit</mark> editor bridges the gap between simple terminal editors and complex IDEs, making it excellent for configuration files and script editing.  


# **Customising Editor Settings**

Each text editor allows customisation to match your preferences and improve productivity. Let's explore common settings for different editors.  

**nano Customisation**

Create a configuration file in your home directory:  
`nano ~/.nanorc`  
Add useful settings:  
`set linenumbers`
`set mouse`
`set softwrap`
`set tabsize 4`
`set autoindent`  
These settings enable line numbers, mouse support, text wrapping, tab size, and automatic indentation.  

**vim Configuration**

Create a vim configuration file:  
`vim ~/.vimrc`  
Add basic improvements:  
`set number`
`set tabstop=4`
`set expandtab`
`set autoindent`
`syntax on`
`set hlsearch`  
This enables line numbers, sets tab width, converts tabs to spaces, enables syntax highlighting, and highlights search results.  

**gedit Preferences**

Access gedit settings through the menu: Edit > Preferences. 

**Editor Tab Settings**

Most editors let you choose between tabs and spaces:  
- <mark>set expandtab</makr>: Converts tabs to spaces
- <mark>set tabstop=4</mark>: Sets tab width to 4 spaces
- <mark>set softtabstop=4</mark>: Makes backspace remove 4 spaces

**Display Options**
Common display customisations:  
- Line numbers for easier navigation
- Syntax highlighting for code files
- Word wrapping for long lines
- Current cursor line highlighting
Start with basic settings and gradually add more as you become comfortable with your chosen editor.  


# **Searching and Replacing Text**

Finding specific text within files is essential for efficient editing. Each editor provides search functionality with different approaches.  

**Searching in nano**

Press <mark>Ctrl+W</mark> to start searching. Type your search term and press Enter. The cursor jumps to the first match.  
For additional matches, press <mark>Ctrl+W</mark> again and press Enter (leave search field empty).  
To search backwards, press <mark>Alt+W</mark>.  

**Searching in vim**

In Normal mode, use these search commands:  
- <mark>/searchterm</mark>: Search forward
- <mark>?searchterm</mark>: Search backward
- <mark>n</mark>: Next match
- <mark>N</mark>: Previous match
Example search:
`/hello`
Press Enter to find "hello" in the text.

**Find and Replace in vim**

Use the substitute command in Normal mode:
`;%s/oldtext/newtext/g`
This replaces all occurrences of "oldtext" with "newtext":
- <mark>%</mark>: Apply to entire file
- <mark>s</mark>: Substitute command
- <mark>g</mark>: Replace all matches on each line
For find and replace, press <mark>Ctrl+F</mark> to open the search bar. Type your search term and the replacement text, then choose "replace" or "Replace ALL".  

**Case Sensitivity**
Most editors support case-insensitivity searching. In <mark>vim</mark>, add <mark>/c</mark> to your search pattern for case-insensitive matching.


# **Saving and Exiting Files**

Properly saving and exiting files prevents data loss and ensures your changes are stored correctly. Each editor has different methods.  

**Saving in nano**

- <mark>Ctrl+0</mark>: Save current file (WriteOut)
- When prompted, press Enter to confirm the filename
- To save with a different name, type the new filename before pressing Enter
To exit nano:
- <mark>Ctrl+X</mark>: Exit the editor
- If unsaved changes exist, nano asks if you want to save
- Press <mark>Y</mark> to save, <mark>N</mark> to discard changes

**Saving and Exiting vim**

All vim commands require Normal mode (press Esc first):
- <mark>:w</mark>: Save current file
- <mark>:w filename</mark>: Save as different filename
- <mark>:q</mark>: Quit vim
- <mark>:wq</mark>: Save and quit
- <mark>:q!</mark.>: Quit without saving (force quit)
The exclamation mark forces the action, useful when vim warns about unsaved changes.  
For quick save and exit:
`:x`  
This saves only if changes if changes were made, then exits.


**Saving in gedit**

Standard shortcuts work in gedit:
- <mark>Ctrl+S</mark>: fSave current file
- <mark>Ctrl+Shift+S</mark>: Save as different filename
- <mark>Ctrl+W</mark>: Close current file
- <mark>Ctrl+Q</mark>: Quit gedit

**Auto-save Features**

Some editors offer automatic saving:
- <mark>gedit</mark>: can auto-save every few minutes
- <mark>vim</mark>: creates swap files for crash recovery
- <mark>nano</mark>: keeps changes in memory until explicitly saved
Always save your work before closing the terminal or shutting down the system.  


# **Best Practices for Editing Configuration Files**ㄹ

Configuration files control how Linux systems and applications behave. Editing them requires careful attention to avoid system problems.  

**Always Create Backups**

Before editing any configuration file, create a backup copy:  
`sudo cp /etc/hosts/ /etc/hosts.backup`  
For files with dates in backup names:
`sudo cp /etc/fstab /etc/fstab.$(date +%Y%m%d)`  

**Use Appropriate Permissions**

Many configuration files require root privileges. Use <mark>sudo</mark> with your editor:  
`sudo nano /etc/ssh/sshd_config`  
Never change file ownership or permissions unless necessary. 

**Understand File syntax**

Configuration files use different formats:
- Lines starting with <mark>//</mark> or <mark>#</mark> are usually comments
- Indentation matters in some files (YAML, Python configs)
- Some files use key=value pairs
- Others use structured formats like JSON or XML

**Validate Before Applying**

Many services provide syntax checking:
`sudo nginx -t`
`sudo apache2ctl configtest`
Test configuration files before restarting services.  

**Common Configuration Locations**

System configurations typically live in <mark>/etc/</mark>: 
- <mark>/etc/hosts</mark>: Network host mapping
- <mark>/etc/tstab</mark>: Filesystem mounting
- <mark>/etc/ssh/sshd_config</mark>: SSG server settings
User configurations are in home directories, often starting with dot.  

**Make Small Changes**

Edit one setting at a time, test the change, then move to the next modification. This approach makes troubleshooting easier if something breaks.  
Keep detailed notes about what you changed and why.
