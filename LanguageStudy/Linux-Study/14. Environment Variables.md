# **Understanding Environment Variables**

Environment variables are special values that your Linux system uses to store information about your computing environment. Think of them as labeled containers that hold data your programs and shell need to function properly. 
These variables tell your system where to find programs, what your username is, which directory you're currently in, and many other important details. Every time you open a terminal or run a program, it can access these variables to understand how it should behave.  
Environment variables have names written in UPPERCASE letters, like <mark>HOME</mark>, <mark>USER</mark>, or <mark>PATH</mark>. Each variable contains a value - for example, <mark>HOME</mark> might contain <mark>/home/alice</mark> if your username is alice.  
Programs use these variables to make decisions. When you type a command like <mark>ls</mark>, your system checks the <mark>PATH</mark> variable to know where to look for the <mark>ls</mark> program. When a program needs to know your username, it reads the <mark>USER</mark> variable.
The beauty of environment variables is that they provide a standard way for all programs to access the same information. Instead of each program figuring out your home directory separately, they all just read the <mark>HOME</mark> variable.  
Your shell creates many environment variables automatically when you log in, but you can also create your own or modify existing ones to customise how your system works.   


## **Viewing and Setting Variables**

To see what environment variables exist on your system, use the <mark>printenv</mark> command:  
`printenv`
This shows all environment variables and their values. To see a specific variable, add its name:  
`printenv HOME`
`printenv USER`
You can also use the <mark>echo</mark> command with a dollar sign before the variable name:  
`echo $HOME`
`echo $USER`
`echo $PATH`
The dollar sign tells the shell to substitute the variable's value instead of printing the literal text.  
To create or change a variable for your current session, use the assignment operator:
`MY_VARIABLE="hello world"`
'EDITOR="nano"'
Remember there are no spaces around the equals sign. After setting a variable this way, you can use it in the same terminal session:
`echo $MY_VARIABLE`
However, variables created this way are only available in your current shell session. They disappear when you close the terminal. 
You can also see all variables (including local shell variables) using the <mark>set</mark> command, though this produces much more output than <mark>printenv</mark>.


# **Persistent Environment Variables**

Variables you set directly in the terminal only last for that session. To make environment variables permanent, you need to add them to configuration files that run automatically when you start your shell.  
For variables that affect only your account, edit the <mark>.bashrc</mark> file in your home directory: 
`nano ~./bashrc`
Add your variable assignments at the end of the file:
`export MY_VARIABLE="permanent value"`
`export EDITOR="nano"`
The <mark>./bashrc</mark> file runs every time you open a new terminal window. After saving the file, either restart your terminal or reload the configuration:
`source ~./bachrc`
For variables you want available to all programs (not just terminal sessions), use <mark>.profile</mark> instead:
`nano ~./profile`
Add the same export statements. The <mark>.profile</mark> file runs when you log into your user account.   
If you want to set variables for all users on the system, you can edit system-wide files like <mark>/etc/environment</mark> or <mark>/etc/profile</mark>, but this requires administrator privileges:
`sudo nano /etc/environment`
In <mark>/etc/environment</mark>, writhe variables without the <mark>export</mark> command:  
`MY_SYSTEM_VAR="system wide value"`
Changes to these files take effect after you log out and log back in.


# **Using export Command**

The <mark>export</mark> command makes variables available to programs you run form your shell. Without <mark>export</mark>, variables only exist within your current shell session and aren't passed to other programs.  
When you create a variable normally, it's only a shell variable:
`MY_VAR="test value"`
This variable exists in your current shell, but programs you run won't see it. To make it an environment variable that programs can access, use <mark>export</mark>:
`export MY_VAR="test value"`
You can also export an existing variable:
`MY_VAR="test value"`
`export MY_VAR`
To see the difference, try this experiment:
`NORMAL_VAR="only in shell"`
`export EXPORTED_VAR="available everywhere"`
`bash`
`echo $NORMAL_VAR  #nothing appears`
`echo $EXPORTED_VAR  #shows the value`
`exit`
The <mark>bash</mark> command starts a new shell session. The normal variable disappears because it wasn't exported, but the exported variable remains available.
You can export multiple variables at once:
`export VAR1="value1" VAR2="value2"`
To remove a variable from the environment, use <mark>unset</mark>:
`unset MY_VAR`
The <mark>export</mark> command is essential when setting permanent variables in configuration files like <mark>./bashrc</mark> or <mark>.profile</mark>.


# **Common Environment Variables**

Linux systems use many standard environment variables that control how your system behaves. Understanding these common variables helps you navigate and customise your environment effectively.  
<mark>HOME</mark> contains the path to your home directory. Most programs use this to know there to store your personal files and settings:
`echo $HOME`
`# typically shows /home/username`
<mark>USER</mark> and <mark>USERNAME</mark> contain your login name:
`echo $USER`
<mark>PATH</mark> lists directories where the system looks for executable programs. This is why you can type <makr>ls</mark> instead of <mark>/bini/ls</mark>:
`echo $PATH`
<mark>PWD</mark> shows your current working directory:
`echo $PWD`
<mark>SHELL</mark> indicates which shell program you're using:  
`echo #SHELL`
`# might show /bin/bash`
<mark>EDITOR</mark> specifies your preferred text editor. Many programs use this when they need to open an editor:
`export EDITOR="nano"`
<mark>LAND</mark> and <mark>LC_ALL</mark> control language and localisation settings:
`echo $LANG`
<mark>TERM</mark> tells programs what type of terminal you're using, which affects how they display text and colours.
These variables work together to create your computing environment. Programs rely on them ot provide consistent behaviour across different systems and user preferences.


# **Customising the Shell Prompt**

Your shell prompt is controlled by the <mark>PS1</mark> environment variable. This variable contains special codes that determine what information appears before your cursor in the terminal.
To see your current prompt setting:
`echo $PS1`
The output contains special escape sequences that start with backslashes. Common ones include:
<mark>\u</mark> shows your username <mark>\h</mark> shows the hostname <mark>\w</mark> shows the current directory <mark>\$</mark> shows <mark>$</mark> for regular users or <mark>#</mark> for root
To change your prompt temporarily:
`PS1="[\u@\h \w]$ "`
This creates a prompt like <mark>[alice@computer~/Documents]$</mark>.
For a simple prompt showing just the directory:
`PS1="\ws$ "`
To add colours, use ANSI colour codes. For a green username:
`PS1="\[\033[32m\]\u\[\033[0m\]@\h:\2$ "`
The <mark>\[\033[32m\]</mark> starts green text, and <mark>\[\033[0m\]</mark> resets to normal colour.
To make prompt changes permanent, add your <mark>PS1</mark> setting to <mark>.bashrc</mark>:
`echo `PS1="[\u@\h \w]$ "` >> ~/.bashrc` 
You can also include the current time with <mark>\t</mark> or date with <mark>\d</mark>:
`PS1="[\t] \u@\h:\w$ "`
Experiment with different combinations to create a prompt that shows the information you find most useful.
